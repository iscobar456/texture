# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

hwscan: a monorepo for writing homework as LaTeX on desktop and pulling in photos of paper/whiteboard work taken on a phone, with the final output being a PDF. Priority platforms: Linux + Android first, macOS + iOS second, Windows if it stays cheap.

## Layout

- `apps/desktop` — Tauri 2 app (Rust shell, vanilla-ts + Vite frontend). CodeMirror 6 editor (stex mode, optional Vim) + PDF.js preview + photo inbox (`src/main.ts`); local-first sync in `src/sync.ts`. Rust commands in `src-tauri/src/lib.rs` own all file access. `compile` shells out to `tectonic`, falling back to `pdflatex`; bundling tectonic as a sidecar is still TODO. Needs `apps/desktop/.env` (see `.env.example`).
- `apps/mobile` — Flutter app (`supabase_flutter`, `image_picker`). Currently: email/password sign-in, take/pick photo, upload to the `photos` bucket and insert a pending row. Not implemented yet: crop/deskew and receiving shared images. `receive_sharing_intent` 1.9 and `image_cropper` 13 were removed because they need compileSdk 37 (Flutter 3.47 defaults to 36 and AGP 9.1 caps at 36; going to 37 also needs AGP 9.2 + Gradle 9.4.1) — pin older versions or upgrade the toolchain when building those features. Config comes from the gitignored `apps/mobile/.env` (see `.env.example`) via `apps/mobile/run.sh`, which wraps `flutter run --dart-define-from-file=.env`.
- `packages/api` — `@hwscan/api`, the TypeScript client/contract for the desktop app (types for `photos`/`assignments`, inbox listing, download, realtime subscription). The Flutter app cannot import it, so the Supabase schema is the real shared contract; keep both clients in step with `supabase/migrations`.
- `supabase/` — migrations (tables, RLS, private `photos` bucket); no edge functions.

## Commands

- Install: `npm install` at the repo root (npm workspaces: `apps/desktop`, `packages/*`).
- Desktop dev: `npm run tauri dev` from `apps/desktop`. Frontend only: `npm run dev`.
- Desktop build: `npm run tauri build` from `apps/desktop`.
- Mobile (Flutter is at `~/flutter/bin`): `apps/mobile/run.sh [flutter run args]`; `flutter analyze` to lint.

## Architecture notes

- Desktop is unusable until signed in (no local-only mode). Documents (identified by a folder path like `Physics/Week 3/HW 1`) and templates are per-account and local-first: files live in the Tauri app data dir (`<app_data_dir>/<user_id>/<folder>/.../<document>/{main.tex,images/,preview.png,.sync.json}` and `.templates/<name>.tex`; on Linux `~/.local/share/dev.hwscan.desktop/`) on purpose, so they are not casually editable and cannot desync from the server; PDFs leave the app only via Menu → Export PDF. Everything works offline. All writes go through `write_atomic` (temp file + rename; temp names start with `.`, which listings ignore). If storage outgrows loose files (search, history, richer sync), SQLite behind the same Rust commands is the intended next step. Built-in templates are embedded in Rust and never synced.
- Sync (`src/sync.ts`; tables `documents`/`templates` + bucket `project-files` from migrations 0002-0004). `documents` holds both documents and folders (`kind` column); folders have empty source. Each local item stores the server `updated_at` it last matched (`remote_at`) plus a `dirty` flag in `.sync.json`. Clean + server newer → pull; dirty + server unchanged → conditional push; dirty + server newer → conflict, server version kept as a local `"<path> (conflict)"` document and the local version pushed. The server clock (trigger `touch_document`, which ignores `preview_at`-only updates) is the version, never client clocks.
- Delete/rename/move: a directory is a document iff it holds `main.tex`, otherwise a folder; documents cannot contain other items. Deleting records a tombstone in `<user_dir>/.deleted.json` (for anything with a `remote_at`) and sync soft-deletes the server row (`deleted_at`), conditional on the deleted version. A server tombstone removes clean local copies, but an edited or never-synced local copy wins and restores the row. Rename and move are the same op (`move_item`): old paths are tombstoned, new paths start dirty with no `remote_at`, so the server sees delete + create (images and previews are re-uploaded under the new path).
- Previews: `preview.png` (page 1 of the last compile) syncs via storage at `<uid>/<path>/preview.png`; `documents.preview_at` is an opaque marker compared for equality only. Images sync for the open document and for documents pulled or newly pushed in a pass. Templates sync and delete the same way (tombstone kind `template`); built-ins can be overridden by saving a template with the same name, and deleting the override reveals the built-in again. A template is edited in the main editor (`templateName` set, saves via `save_template`, compiles in `.scratch`).

- Phone → desktop flow: the phone uploads to the private `photos` bucket at `<user_id>/<file>` and inserts a `photos` row with `status = 'pending'`. The desktop subscribes to realtime changes to `photos` (`onInboxChange`, which also covers deletes), downloads the image, and marks the row `imported`. Storage RLS depends on that `<user_id>/` path prefix.
- OCR-to-LaTeX runs on the desktop with the user's own Anthropic API key (Settings → Photo OCR). The key is saved by Rust in `<user_dir>/.api_key` (owner-only, device-local, never synced, never returned to the webview); `ocr_image` in `lib.rs` shrinks nothing itself — the webview downscales the photo to ≤1568px JPEG first — and calls api.anthropic.com with effort `low` (thinking tokens are billed as output). Models are an allowlist (`OCR_MODELS` in `lib.rs` and `settings.ts`, keep in step; prices in `settings.ts` drive the cost shown after each run). The result is inserted at the cursor for review, never auto-compiled. `photos.ocr_latex` is now unused.
- Realtime only works while an app is foregrounded. Background push on mobile would need FCM/APNs.
- Keep all backend access behind `packages/api` (desktop) so the backend can be swapped (e.g. PocketBase) later.
- User settings (`apps/desktop/src/settings.ts`: theme, editor color scheme (palettes are CSS variable blocks keyed by `data-editor-theme`; `--cm-line` must stay translucent or it hides the selection), editing mode, font size, wrap, line numbers, auto-compile, default template) are per-device in `localStorage` under `hwscan:settings`, not synced. Theme works by setting `data-theme` on `<html>`; with none set, CSS follows the OS.
- Autocomplete (`apps/desktop/src/completions.ts`): one CodeMirror completion source (`latexSource`, registered via `EditorState.languageData`) for commands, `\begin{}` environments (inserts an `\end` skeleton), `\ref{}` labels scraped from the document, packages and word snippets. User snippets (trigger and/or keyboard shortcut, CodeMirror snippet syntax with `#{}` tab stops) are edited in `snippets-ui.ts`, stored per-device in `localStorage` (`hwscan:snippets`, not synced), and shortcuts live in `snippetSlot` at highest precedence ahead of `vim()`; they are skipped in Vim normal/visual mode. No LSP; `texlab` over a Tauri-spawned process would be the route if needed.
